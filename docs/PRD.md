# 产品需求 v0.1

## 定位
帮助设计学生和小型创作团队，将分散的项目素材整理为可比较、可追溯、可批量交付的设计资产。
待验证的问题来自BAMOR复盘：阶段和版本混杂、比较与取舍分散、重复排版命名、生成结果不易追溯。
当前尚无外部访谈或效率基线。先做实际流程，再测量。

## 核心流程
导入素材 → 按来源/阶段筛选 → 按自然语言需求进行AI初筛与解释 → 人工确认/比较/标注 → 保存 → 后续批量生产对比图和素材卡 → 导出记录。

## M1 素材筛选与记录
- 默认先展示说明和“导入8份BAMOR样例”的明确入口，重复导入不可造成重复记录。
- 支持真实上传PNG/JPEG/WebP。显示文件名、预览、来源、阶段、标签和审核状态。
- 上传文件与预览Blob持久保存，刷新后能恢复。元数据和图片通过稳定ID关联。
- 搜索标题/标签，筛选学期、来源、内容类型与审核状态。提供筛选后数量与空结果状态。
- 选择2—4项并排对比，可取消选择。4项不是固定必须选满。
- 编辑标题、阶段、材料、标签、通过/淘汰和原因，评分按人工量表输入，初始为空。
- CSV导出记录；JSON备份应包含可恢复的必要信息。记录恢复能力与图片恢复范围要明确。
- 当前目录样例数据与新增上传分开，不把样例清单改写成审核结果。
- 界面清晰、排版克制，采用浅底深字，素材预览是主体。信息不足时不要虚构业务指标。

## M2 自然语言AI选图（2026-10-22调整为下一阶段优先项）
- 用户输入用途、需要张数、希望突出内容和必须条件，以当前筛选结果作为候选范围。
- 服务端调用具备视觉能力的真实模型，并把实际候选图片逐张作为图像输入；不得只根据文件名、标题或标签判断。
- 返回推荐顺序、每张图的任务作用、可见图像依据、与需求的关系、其他候选未推荐原因及无法确认的信息。
- 模型可建议描述性标题；学期、来源等事实只引用元数据，重量、性能和贡献归属等无法确认的信息保持未知。
- AI建议按具体任务独立保存，人工确认另存；不覆盖素材现有人工评分、理由或审核状态，也不把本次未推荐等同永久淘汰。
- 凭证只放在服务端。未配置模型时明确显示未连接，不得用写死、随机或模拟结果冒充真实调用。
- 使用现有图片分别测试“选择作品封面”和“解释网格壳体构型”，真实记录模型、响应ID、图片数量与测试结果；缺少服务配置时记录为未执行。

## M3 设计素材生产自动化（顺延）
- 对选中素材批量生成1:1、4:5、16:9素材卡。默认等比完整放入，允许留边，避免裁去实验文字。
- 素材卡包含图像、短标题、阶段/版本及可选来源，控制字号和行距。
- 将2—4个素材排为PNG对比板，附标题与取舍说明。
- 按统一规则命名，图像与CSV/JSON清单可一一对应。保留源素材ID与模板版本。
- 导出前提供预览，图片未加载或导出失败要显示可理解的反馈。
- M3自动化的是排版、命名和交付，不显示为已接入AI图像生成。

## M4 生成任务组织
读取12个planned任务，展示结构约束、场景与光照。生成可复制提示词，供用户去真实平台生成。
用户回传结果后记录结果素材ID、平台、模型、时间、提示词和版本，再进行人工审美与一致性审核。
先支持手动回传，后续再决定是否接API或ComfyUI。

## M5 可选扩展
真正接通生成服务、任务队列和失败重试之后，再考虑明确角色的Agent流程。
角色可包括需求整理、任务规划、结果审核，但必须有可运行的输入输出和调用记录。

## 当前不作为首版要求
账号/支付、团队在线协作、LoRA训练、自动决定结构安全、ROS实体控制、完整RAG系统。
